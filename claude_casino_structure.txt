**Резервирование и победитель** — ключевой backend-контракт:

```java
// WinnerService.java — weighted RNG endpoint
public WinnerResult determineWinner(RoomParams room) {
    List<Slot> slots = room.getSlots(); // real users + bots
    // Each slot weight = 1 + (hasBust ? boostMultiplier : 0)
    double totalWeight = slots.stream()
        .mapToDouble(s -> s.isBoosted() ? room.getBoostMultiplier() : 1.0)
        .sum();
    double roll = ThreadLocalRandom.current().nextDouble(0, totalWeight);
    double cursor = 0;
    for (Slot s : slots) {
        cursor += s.isBoosted() ? room.getBoostMultiplier() : 1.0;
        if (roll <= cursor) return new WinnerResult(s.getParticipantId(), roll, totalWeight);
    }
    return new WinnerResult(slots.getLast().getParticipantId(), roll, totalWeight);
}
```

**Буст — прозрачная логика (требование ТЗ):**
```java
// Boost multiplies the slot weight in the RNG pool
// Example: room has 6 slots, user buys boost (cost = 50% of entry)
// Without boost: user has 1/6 = 16.7% win probability
// With boost (multiplier=2.0): user has 2/8 = 25.0%
// This is shown explicitly in the UI before purchase

public double calculateBoostedProbability(Room room, boolean hasBust) {
    int slots = room.getMaxSlots();
    double boostMult = room.getBoostMultiplier(); // configurable
    double totalWeight = (slots - 1) * 1.0 + (hasBust ? boostMult : 1.0);
    double userWeight = hasBust ? boostMult : 1.0;
    return userWeight / totalWeight; // shown in UI as percentage
}
```

```typescript
// Frontend config validation — shows warnings live
function analyzeConfig(cfg: RoomConfig): ConfigWarnings {
  const rtp = cfg.prizePoolPct / 100; // e.g. 0.80
  const houseEdge = 1 - rtp;          // 0.20 = 20%
  const boostRevenue = cfg.boostCost * cfg.maxSlots * cfg.estimatedBoostRate;
  
  return {
    lowAttractiveness: rtp < 0.70,    // warn: prize pool too small
    highRisk: houseEdge < 0.05,       // warn: operator margin too thin
    boostOverpowered: cfg.boostMultiplier > 3.0, // warn: breaks economy
    estimatedROI: houseEdge + boostRevenue / (cfg.entryPrice * cfg.maxSlots)
  };
}
```

## Q&A Readiness

**«Почему не полное разделение фронта и бэка на разных доменах?»** — MVP намеренно монолитен для скорости демо; архитектура описана так, что Gateway/BFF можно добавить за один спринт.

**«Как гарантировать честность RNG?»** — WinnerService логирует seed, roll, totalWeight и participantId в audit-таблицу; эксперт может верифицировать любой раунд через панель журнала (Сценарий 8 из ТЗ).

**«Что если бот победил и фонд остался в системе?»** — это фича, не баг: bot-wins увеличивают house edge, что экономически выгодно организатору и явно описано в конфигураторе как параметр.
